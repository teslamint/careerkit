### 솔루션 보유 SI 판별 (SI 업계를 스크리닝 범위에 두는 경우)

자사 솔루션의 존재만으로 SI 리스크 해소로 보지 않는다. 실질 3요소로 판단:

1. 근무 형태 — 본사 개발 vs 고객사 상주 비율
2. 업무 내용 — 제품 코드베이스 개발 vs 고객사 운영·유지보수
3. 제품의 고객 수·파이프라인 — 단일 고객이면 소속 라벨과 무관하게
   단일 고객 종속 SI로 평가

## 0.5️⃣ 증거 사용 원칙 (메타 규칙)

판정 품질을 지키는 계층. 개별 기준보다 우선 적용된다.

### ① 증거 계층

자격요건·우대사항·주요업무 = 1차 증거. 회사소개·브랜딩 = 2차 증거.
상충 시 1차 우선, 근거 불충분 시 컷 대신 보류.

### ② JD 신선도

{N일} 이상 지난 스크리닝을 인용하려면 재조회(제목·업무·요건 diff 포함).
재조회 전 source URL(플랫폼) 확인 — 숫자 ID는 플랫폼 간 충돌 가능.

### ③ 이력/경험 매칭

- 이력에 명시된 근거가 있는 항목만 매칭으로 본다
- 일반 경험에서 구체 경험을 추론하지 않는다
- 복합 요건은 하위 요소로 분해해 대조, 근거 없는 요소는 서류 사용 금지
- 집계: 완전 충족 / 대부분 충족(공백 명시) / 부분 충족 / 미충족

### ④ 보류 판정 형식

보류(🟡) 문서에는 추천 전환 조건과 비추천 확정 조건을 쌍으로 명시한다.
반전 조건 없는 보류는 불완전 판정.

### ⑤ 고용형태

{계약직 처리 방침 — 예: 12개월 미만 계약은 자동 컷 아닌 보류 경로}
